# Greenhouse Gases

Веб-сервис для работы с данными о парниковых газах и расчёта изменения средней температуры Земли в зависимости от содержания парниковых газов в атмосфере.

Проект является продолжением лабораторной работы №1. В лабораторной работе №2 существующая архитектура FastAPI-приложения расширяется полноценной базой данных PostgreSQL с использованием SQLAlchemy ORM и Alembic.

## Тема проекта

**Прогноз температуры на Земле в зависимости от содержания парниковых газов в атмосфере.**

В приложении рассматриваются:

* углекислый газ (CO₂);
* метан (CH₄);
* оксид азота (N₂O);
* водяной пар (H₂O);
* гексафторид серы (SF₆).

Основная задача сервиса — хранение информации о парниковых газах и расчёт изменения температуры в зависимости от заданной концентрации.

Основной объект системы — **парниковый газ**.

Для каждого объекта могут храниться:

* название;
* химическая формула;
* краткое описание;
* концентрация;
* потенциал глобального потепления GWP100;
* рассчитанное изменение температуры;
* статус;

* видео;
* дата создания;
* создатель;
* дата публикации.

Пользователь может быть создателем парникового газа и может поставить лайк опубликованному объекту.

# Модель базы данных

В лабораторной работе используется PostgreSQL.

База данных содержит три основные таблицы:

```text
users
greenhouse_gases
likes
```

## users

Таблица пользователей.

| Поле       | Назначение       |
| ---------- | ---------------- |
| `id`       | Первичный ключ   |
| `username` | Имя пользователя |

## greenhouse_gases

Основная таблица предметной области.

| Поле                            | Назначение                |
| ------------------------------- | ------------------------- |
| `id`                            | Первичный ключ            |
| `name`                          | Название парникового газа |
| `formula`                       | Химическая формула        |
| `short_description`             | Краткое описание          |
| `status`                        | Статус объекта            |
| `image_url`                     | URL изображения           |
| `video_url`                     | URL видео                 |
| `concentration_ppm`             | Концентрация              |
| `temperature_change_c`          | Изменение температуры     |
| `created_at`                    | Дата создания             |
| `creator_id`                    | Создатель                 |
| `published_at`                  | Дата публикации           |
| `global_warming_potential_100y` | GWP100                    |

`creator_id` является внешним ключом на `users.id`.

## likes

Таблица связывает пользователей и парниковые газы.

| Поле                | Назначение                     |
| ------------------- | ------------------------------ |
| `user_id`           | Внешний ключ на пользователя   |
| `greenhouse_gas_id` | Внешний ключ на парниковый газ |

Пара:

```text
user_id + greenhouse_gas_id
```

является составным первичным ключом.

Таким образом реализуется отношение:

```text
users
   │
   │ 1:N
   ▼
 likes
   ▲
   │ N:1
   │
greenhouse_gases
```

Один пользователь может поставить лайк нескольким парниковым газам, а один парниковый газ может иметь лайки от нескольких пользователей.

# Статусы парникового газа

Для объектов используются три состояния:

```text
черновик
опубликован
удален
```

### Черновик

Новая заявка пользователя, которая ещё не опубликована.

### Опубликован

Парниковый газ доступен пользователям в каталоге и ленте.

### Удален

Объект считается удалённым логически.

Физического удаления строки из PostgreSQL не происходит.

Для удаления используется SQL-запрос:

```sql
UPDATE greenhouse_gases
SET status = 'удален'
WHERE id = :greenhouse_gas_id;
```

Удалённые объекты не отображаются в каталоге и ленте.

При обращении к их прямому URL содержимое также не выводится.

# Работа с заявками

Пользователь может создать заявку на добавление парникового газа.

Сначала создаётся объект со статусом:

```text
черновик
```

Для одного пользователя используется не более одного активного черновика.

Создание черновика выполняется через SQLAlchemy ORM.

После заполнения необходимых данных черновик может быть опубликован.

При публикации сохраняются:

* описание;
* химическая формула;
* GWP100;
* концентрация;
* рассчитанное изменение температуры;
* статус;
* дата публикации.

Публикация также выполняется через SQLAlchemy ORM.

# Расчёт температуры

Для учебного проекта используется упрощённая математическая модель:

```text
ΔT = S × log₂(C / C₀)
```

где:

* `C` — концентрация;
* `C₀ = 280 ppm` — базовая концентрация;
* `S = 3 °C` — используемая в проекте климатическая чувствительность.

В приложении:

```python
REFERENCE_CO2_PPM = 280.0
CLIMATE_SENSITIVITY_C = 3.0
```

Результат сохраняется в поле:

```text
temperature_change_c
```

# HTTP-интерфейс

В лабораторной работе реализованы необходимые GET и POST-запросы.

## GET

### Лента

```text
GET /greenhouse-gases/{greenhouse_gas_id}
```

Отображает опубликованный парниковый газ.

Для перехода к следующему опубликованному объекту используется:

```text
GET /greenhouse-gases/{id}?next=true
```

### Каталог

```text
GET /greenhouse-gases/catalog
```

Отображает опубликованные парниковые газы.

Фильтрация выполняется на сервере:

```text
GET /greenhouse-gases/catalog?concentration=420
```

### Заявка

```text
GET /greenhouse-gases/request
```

Отображает страницу создания и публикации заявки.

---

# POST

### Создание черновика

```text
POST /greenhouse-gases/request
```

Создаёт новую запись со статусом:

```text
черновик
```

### Публикация

```text
POST /greenhouse-gases/publish
```

Переводит существующий черновик в статус:

```text
опубликован
```

### Логическое удаление

```text
POST /greenhouse-gases/{greenhouse_gas_id}/delete
```

Изменяет статус объекта на:

```text
удален
```

# Работа с базой данных

Для взаимодействия с PostgreSQL используется:

**SQLAlchemy 2.x + AsyncSession**

Подключение к базе данных выполняется асинхронно.

Основные компоненты:

```text
db/base.py
db/session.py
models/
repositories/
```

Модели SQLAlchemy:

```text
models/user.py
models/greenhouse_gas.py
models/like.py
```

Работа с данными вынесена в репозиторий:

```text
repositories/greenhouse_gas.py
```

ORM используется для:

* создания черновика;
* публикации;
* получения опубликованных объектов;
* получения черновика;
* получения количества лайков.

Для логического удаления используется отдельный SQL `UPDATE`, что позволяет продемонстрировать работу с базой данных не только через ORM.

Для управления структурой PostgreSQL используется **Alembic**.

Текущая последовательность миграций:

```text
d617e03f4939
       ↓
387e381fb912
       ↓
9f4a7c2b1d30
```

Применение миграций:

```bash
alembic upgrade head
```

Создание новой миграции:

```bash
alembic revision --autogenerate -m "description"
```

# WEB-26-GREENHOUSE-GASES-BACK

## Лабораторная работа №3

### Тема проекта

**Прогноз температуры на Земле в зависимости от содержания парниковых газов в атмосфере**

В рамках лабораторной работы №3 разработан REST API для работы с парниковыми газами, пользователями и отметками «Нравится».

REST API позволяет получать опубликованные парниковые газы, выполнять серверную фильтрацию, создавать черновики, загружать изображения и видео в MinIO, публиковать и мягко удалять записи, ставить и отменять лайки, а также регистрировать пользователей.

Лабораторная работа является продолжением лабораторной работы №2.

# Предметная область

Приложение посвящено прогнозированию изменения температуры Земли в зависимости от содержания парниковых газов в атмосфере.

Для каждого парникового газа хранятся:

* название;
* химическая формула;
* краткое описание;
* потенциал глобального потепления за 100 лет;
* концентрация;
* рассчитанное изменение температуры;
* изображение;
* короткое видео;
* статус;
* дата создания;
* создатель;
* дата публикации.

### Расчёт изменения температуры

В проекте используется формула:

**ΔT = S × log₂(C / C₀)**

где:

* `ΔT` — изменение температуры в °C;
* `S = 3.0 °C` — климатическая чувствительность;
* `C` — концентрация парникового газа;
* `C₀ = 280 ppm` — эталонная концентрация CO₂.

Расчёт выполняется при создании парникового газа, если указана его концентрация.

# REST API

API имеет общий префикс:

```text
/api
```

REST API разделён на два домена:

1. домен приложения;
2. домен пользователя.

---

# Домен приложения

## 1. Получение списка с фильтрацией

```http
GET /api/greenhouse-gases
```

Метод возвращает список только **опубликованных** парниковых газов.

Для серверной фильтрации используется параметр:

```http
GET /api/greenhouse-gases?concentration=500
```

Параметр `concentration` позволяет получить парниковые газы, концентрация которых не превышает указанное значение.

Фильтрация выполняется непосредственно на стороне базы данных.

В каждом элементе ответа также присутствует:

```text
is_creator
```

Значения:

```text
1 — текущий пользователь является создателем;
0 — текущий пользователь не является создателем.
```

Пример ответа:

```json
[
  {
    "id": 1,
    "name": "CO2",
    "formula": "CO₂",
    "global_warming_potential_100y": 1,
    "short_description": "Диоксид углерода",
    "concentration_ppm": 420,
    "temperature_change_c": 1.7,
    "image_url": "...",
    "video_url": "...",
    "is_creator": 1
  }
]
```

---

## 2. Получение ленты

```http
GET /api/greenhouse-gases/published-gases
```

Метод возвращает опубликованные парниковые газы для отображения в ленте.

Для каждого объекта возвращаются:

* информация о парниковом газе;
* изображение;
* видео;
* количество лайков;
* признак наличия лайка текущего пользователя.

Используется поле:

```text
is_liked
```

где:

```text
1 — текущий пользователь поставил лайк;
0 — текущий пользователь не поставил лайк.
```

Для получения следующего опубликованного газа используется параметр текущего GET-запроса:

```http
GET /api/greenhouse-gases/published-gases?greenhouse_gas_id=5&next=true
```

В данном случае API находит первый опубликованный объект с идентификатором больше указанного.

`next=true` является параметром существующего GET-метода и **не является отдельным HTTP-методом**.

---

## 3. Получение черновика

```http
GET /api/greenhouse-gases/my-gas
```

Метод возвращает черновик текущего пользователя.

Идентификатор пользователя или парникового газа в URL не передаётся.

Текущий пользователь определяется с помощью зависимости FastAPI.

Для одного пользователя допускается не более одного черновика.

Если черновик отсутствует, API возвращает ошибку `404 Not Found`.

---

## 4. Добавление парникового газа

```http
POST /api/greenhouse-gases
```

Метод создаёт новый черновик парникового газа.

Для запроса используется `multipart/form-data`.

Передаются следующие данные:

```text
name
formula
global_warming_potential_100y
short_description
concentration_ppm
image
video
```

`image` и `video` передаются как файлы.

Изображение и видео загружаются в MinIO.

В базе данных сохраняются сгенерированные имена файлов.

Например:

```text
image_8c1f...jpg
video_4a72...mp4
```

Имена файлов генерируются на латинице.

Если указана концентрация газа, сервер рассчитывает изменение температуры по формуле:

```text
ΔT = S × log₂(C / C₀)
```

После успешного создания запись получает статус:

```text
черновик
```

---

## 5. Публикация парникового газа

```http
PUT /api/greenhouse-gases/{greenhouse_gas_id}/publish
```

Метод переводит черновик текущего пользователя в статус:

```text
опубликован
```

Также устанавливается дата публикации:

```text
published_at
```

Пользователь не может опубликовать чужой черновик.

Пример ответа:

```json
{
  "id": 5,
  "name": "CO2",
  "status": "опубликован",
  "image_url": "...",
  "video_url": "...",
  "published_at": "2026-10-08T20:15:00"
}
```

---

## 6. Удаление парникового газа

```http
DELETE /api/greenhouse-gases/{greenhouse_gas_id}
```

Метод выполняет только **мягкое удаление**.

Запись не удаляется физически из PostgreSQL.

Вместо этого её статус изменяется:

```text
опубликован → удален
```

Удалять можно только парниковые газы текущего пользователя.

Удалённые записи не отображаются в списке опубликованных объектов и ленте.

---

## 7. Работа с отметкой «Нравится»

```http
POST /api/greenhouse-gases/{greenhouse_gas_id}/like
```

Метод изменяет состояние лайка текущего пользователя.

Тело запроса:

```json
{
  "like": 1
}
```

Используются два значения:

```text
1 — поставить лайк;
0 — отменить лайк.
```

При `like = 1` в таблицу `likes` добавляется связь между текущим пользователем и парниковым газом.

При `like = 0` существующая связь удаляется.

В ответе возвращается актуальное количество лайков.

Пример:

```json
{
  "greenhouse_gas_id": 5,
  "like": 1,
  "likes_count": 3
}
```

# Текущий пользователь

В лабораторной работе №3 используется фиксированный текущий пользователь:

```python
CURRENT_USER_ID = 1
```

Получение пользователя реализовано в `api/dependencies.py`:

```python
def get_current_user_id() -> int:
    return CURRENT_USER_ID
```

Использование в HTTP-обработчиках:

```python
current_user_id: int = Depends(get_current_user_id)
```

Таким образом, операции создания, публикации, удаления и постановки лайков выполняются от имени фиксированного пользователя.

Полноценная авторизация будет добавлена в лабораторной работе №4.

# Хранение файлов

Для хранения изображений и видео используется MinIO.

Используемый bucket:

```text
climate-media
```

Файлы передаются в API как `UploadFile`.

После загрузки:

1. сервер проверяет тип файла;
2. генерирует уникальное имя на латинице;
3. загружает файл в MinIO;
4. сохраняет имя файла в PostgreSQL.

Пример:

```text
MinIO:

climate-media/
├── image_a81f...jpg
└── video_39bc...mp4

PostgreSQL:

image_url = image_a81f...jpg
video_url = video_39bc...mp4
```

## Структура базы данных

Для хранения данных используется PostgreSQL.

В базе данных используются три таблицы:

```text
greenhouse_gases
users
likes
```

### `greenhouse_gases`

```text
id                           INTEGER PK
name                         VARCHAR
formula                      VARCHAR
global_warming_potential_100y FLOAT
short_description            TEXT
status                       VARCHAR
image_url                    TEXT
video_url                    TEXT
concentration_ppm            FLOAT
temperature_change_c         FLOAT
created_at                   DATETIME
creator_id                   INTEGER FK → users.id
published_at                 DATETIME
```

### `users`

```text
id          INTEGER PK
username    VARCHAR UNIQUE
password    VARCHAR
```

### `likes`

```text
user_id             INTEGER PK, FK → users.id
greenhouse_gas_id   INTEGER PK, FK → greenhouse_gases.id
```

Таблица `likes` использует составной первичный ключ из `user_id` и `greenhouse_gas_id`, поэтому один пользователь не может создать несколько одинаковых отметок «Нравится» для одного парникового газа.

Связи между таблицами:

```text
users
  │
  ├── 1 : N ── greenhouse_gases
  │              creator_id
  │
  └── 1 : N ── likes
                  user_id
                       │
                       N : 1
                       │
                greenhouse_gases
                  greenhouse_gas_id
```

Удаление парникового газа выполняется логически: запись сохраняется в таблице `greenhouse_gases`, а её статус изменяется на `удален`.

Структуру базы данных и связи ORM-моделей можно просмотреть в исходном коде проекта и через Adminer.
